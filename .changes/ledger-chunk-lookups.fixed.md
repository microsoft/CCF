`GET` and `HEAD` `/node/ledger_chunk?since=<seqno>` no longer wait for the ledger's file operations, such as the fsync of a completed chunk, to find the committed chunk containing the seqno, so on slow ledger storage they no longer take up the threads serving other requests.
With `include_committed_prefix=true`, requests still wait for those operations when no committed chunk contains the seqno; see [Download Endpoints](doc/operations/ledger_snapshot.rst#download-endpoints).
